# `worktree branch`

Create a new branch in a dedicated worktree.

## Usage

```bash
worktree branch <name>
worktree branch <name> --source <remote-branch>
worktree branch --github <issue-number>
worktree branch --github <issue-number> --assign
worktree branch --github <issue-number> --no-assign
worktree branch --jira <issue-id>
worktree branch <name> --agent "<prompt>"
```

## Examples

```bash
worktree branch feature/add-bulk-actions
worktree branch feature/add-bulk-actions --source origin/release/1.4
worktree branch --github 42
worktree branch --github "#42"
worktree branch --github 42 --assign
worktree branch --github 42 --no-assign
worktree branch --jira DEV-123
worktree branch --jira dev-123
worktree branch feature/add-bulk-actions --agent "add bulk actions to the table"
worktree branch --github 42 --agent "implement the issue"
```

## GitHub Issue Branching

Use the `--github` flag to create a suggested branch name from an issue in the current repository.

- The issue number can be passed as `42` or `"#42"`.
- The generated name is pre-filled in the prompt and still editable.
- If issue types are configured in the repository, these optional prefixes are applied:
	- `branchPrefix.feature` for issue type `Feature`
	- `branchPrefix.bugfix` for issue type `Bug`
	- `branchPrefix.chore` for issue type `Task`

If no prefix is configured, `worktree` falls back to an empty prefix and still generates a valid branch name.

GitHub authentication is resolved in this order:

1. `northguild.worktree.github.token` from local git config.
2. `gh auth token` if GitHub CLI is installed and authenticated.
3. Interactive token prompt, which is then saved in local git config.

### Assigning the issue to yourself

`--assign` assigns the issue to the authenticated user as part of creating the branch, and `--no-assign`
skips it for that one run. Without either flag the decision comes from
[`github.autoAssign`](/docs/configuration#github-integration-notes), and if that key is unset you are asked
once — your answer is saved to it, so the question is not repeated.

```bash
worktree branch --github 42 --assign
worktree branch --github 42 --no-assign
worktree config github.autoAssign true    # always assign, stop asking
```

- **Assigning requires a token with push access to the repository.** Reading an issue does not, so a public
  repository that `--github` has always worked against without a token may ask for one the first time you
  assign — the resolution order above still applies, so an authenticated `gh` supplies it silently.
- Success is confirmed against the API response rather than assumed. If the issue comes back without you on
  it, `worktree` says so instead of reporting success — GitHub can accept an assignee change and ignore it
  when the token lacks push access.
- **A failed assignment never stops the branch.** The worktree is created either way; you get a warning, not
  an error.
- The assignment happens before the worktree is created, so the question is never buried behind creation
  output or a launched editor. Assigning is idempotent — GitHub does not replace existing assignees — so
  retrying after a failed creation is harmless.
- `--assign` and `--no-assign` both require `--github` or `--jira`; on their own there is no issue to act
  on. `--assign --jira` warns that Jira assignment is not supported yet and carries on.

## Jira Issue Branching

Use the `--jira` flag to create a suggested branch name from an issue in your Jira workspace.

- The issue ID can be passed in any case (`dev-123`, `DEV-123`, etc.).
- The generated name is pre-filled in the prompt and still editable.
- If issue types are configured in the repository, these optional prefixes are applied:
	- `branchPrefix.feature` for issue types like `Feature`, `Story`, and most non-bug/chore types
	- `branchPrefix.bugfix` for issue type `Bug`
	- `branchPrefix.chore` for issue type `Task`

If no prefix is configured, `worktree` falls back to an empty prefix and still generates a valid branch name.

Jira authentication requires three configuration keys:

1. `northguild.worktree.jira.host` - Your Jira workspace URL (e.g., `https://company.atlassian.net`)
2. `northguild.worktree.jira.email` - Your Jira email address
3. `northguild.worktree.jira.apiToken` - Your Jira API token

## Agent Dispatch

Use the `--agent` flag (short: `-a`) to hand the new worktree to the coding agent configured as
[`agent.command`](/docs/configuration#agent-command). The flag's value is the prompt the agent starts with.

```bash
worktree branch feature/add-bulk-actions --agent "add bulk actions to the table"
```

- The agent runs **with the new worktree as its working directory**, so it works inside
  `<repo>.worktrees/<branch-name>` rather than picking a directory of its own.
- The prompt is passed as a **single argument**, so quotes, apostrophes and semicolons in it reach the
  agent unchanged. No shell interprets it.
- The agent is started and left running — `worktree` does not wait for it, and its output does not appear
  here. Use your agent's own tooling to follow it.
- `--agent` and the editor are **independent**: if `codeEditor` is configured, the worktree still opens in
  it as well.
- If `agent.command` is not configured, `worktree` says so and carries on — the worktree is still created
  and the editor still opens.

## What It Does

1. Assigns the issue to you, when creating from `--github` and assignment is enabled.
2. Creates a branch from your configured source branch.
3. Adds a worktree under `<repo>.worktrees/<branch-name>`.
4. Copies the gitignored env files into the new worktree — see
   [Environment Files](/docs/guides/env-files).
5. Starts the configured coding agent in it (with `--agent`).
6. Opens the worktree in your configured editor (if configured), or as a Herdr space when `opener` is `herdr`.
